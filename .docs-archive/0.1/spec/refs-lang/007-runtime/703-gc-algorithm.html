      #7.3. GC algorithm

      rok's GC is a collector that layers sticky mark-bit generational collectionwhippet on top of Immix mark-regionimmix. Minor collection and evacuation are stop-the-world, with mutators stopped at safepoints (8.4). The mark phase of a full collection may run concurrently (7.5). Roots and the write barrier are defined in 7.4.

      #7.3.1. Immix mark-region

      #Blocks and lines

      block (32 KiB) = line (128 B) × 256

      Blocks are obtained from the OS (mmap). Objects may cross line boundaries. Mark marks the object together with the lines it spans, and sweep reclaims unmarked lines. Small gaps between live objects are reused at line granularity.

      #Sweep: block classification

      ClassStateHandling
      cleanAll lines emptyTo the free pool
      recyclableOnly some lines liveFree lines reused for allocation
      fullNearly all lines liveLeft as is

      Sweep does not zero dead objects, except secret buffers (WIPE, 7.1.2). The allocator zeroes lines when it fills a TLAB.

      #Opportunistic evacuation

      A full collection may move live objects out of fragmented blocks into other blocks.

      • Candidates are chosen from the line state left by the previous sweep (blocks at most half full). Objects are moved only when a fragmentation threshold is exceeded.
      • A forwarding pointer is left at a moved object's old location, and all precise references are updated to the new location within the same collection.
      • Objects not moved: objects pointed to directly by roots (7.4.1), objects pointed to by ambiguous words (AMBIGUOUS_WORD: type id 2 buffers, untagged unions), PINNED / NOMOVE objects, and LOS objects.
      • Free blocks beyond the next cycle's allocation budget are returned to the OS.
      • For testing, ROK_GC_EVAC=always evacuates on every full collection (9.9.8).

      #7.3.2. Sticky mark-bit generational collection

      There is no separate nursery space; generations are distinguished by the header's STICKY bit (8.1.3). An object that survives a collection gets STICKY set and becomes old. Objects stay in place; there is no promotion copy.

      CollectionMark starting pointsScope
      minor (young)Roots, remembered set, dirty cards (7.4.2)Does not enter old objects. Sweep covers only lines handed out since the last collection
      full (old)RootsClears all STICKY and does a full mark / sweep
      • Young lines are parsed only in blocks reached by an object lookup.
      • A full collection happens when the bytes of old objects reach max(4 MiB, live after the previous full collection × 2), or when rok_gc_collect is called.

      #7.3.3. Mark procedure

      1. Start from the roots (7.4.1).
      2. For each reached object, set MARK in the header, mark the lines it spans, and follow its children through the ScanTable of its type_id.
      3. Finish when the queue is empty.

      ScanTables are registered with rok_gc_register_type (8.5.1).
