      #8. Runtime ABI / MLIR lowering overview

      This block defines the shared contract between the compiler (rokc) and the runtime (librokr.a). The compiler and the runtime are connected through the text of this specification. The only code they share is a single definition of the GC ABI constants (gc_abi, 8.1).

      #Two kinds of contract

      #1. Runtime ABI

      The interface used when compiler-generated code is linked and run together with librokr.a. The memory layout of objects is specified so that the GC can interpret compiler-created objects exactly. Extern "C" symbols are runtime functions the compiler may call; the thread-safety class of each symbol (thread-safe / caller-thread-only / process-init, etc.) is defined in 8.5 Extern "C" symbols. TLS slots are thread-local locations read and written by inline code the compiler emits. The calling convention specifies register and stack usage in function calls.

      #2. MLIR lowering

      The rules, applied in the rok-mir → standard MLIR stage of the compilation pipeline, that translate rok's high-level semantics into standard MLIR dialects. tagged union, any slots, pattern matching, try/catch and generics are all lowered to standard MLIR dialects. There is no custom rok dialect.

      #Why this specification text is authoritative

      The compiler and the runtime share no code or header files other than gc_abi. The guarantee that both follow the same ABI comes from this specification text and from end-to-end verification in integration tests.

      This model follows the same approach as Swift ABI Stability: the specification is authoritative and the implementation follows it.

      #Stability

      The contract in this block is part of the language version (SemVer). ABI changes come with an explicit version bump. Minor / patch releases may only add and must not break compatibility. Major releases may break compatibility, but do so in a way the package manager can detect.

      The ROKHIR header of a prebuilt package records the rokc that built it (9.4). Using a package built by a different rokc is an error that asks for a rebuild.
