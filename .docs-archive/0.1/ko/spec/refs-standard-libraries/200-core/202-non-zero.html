      #2.2. niche wrapper - NonZero / NonNan / Finite / Positive

      rok::core::num::niche 는 값의 부분집합을 강제하는 wrapper 를 둡니다. 각 wrapper 는 #[niche(..)] (refs-lang 2.7.4) 를 붙인 newtype 이며, 빠진 값이 T | none 의 niche 가 됩니다.

      #2.2.1. 크기

      niche 가 있는 T | none 은 T 의 크기입니다 (refs-lang 2.7.2). none 은 그 niche 값으로 표현되며, 실제 비트는 구현이 정합니다.

      타입T | none 크기none 의 niche 값
      i32 | none8 B (태그)없음
      NonZero<i32> | none4 B0
      f64 | none16 B (태그)없음
      NonNan<f64> | none8 BNaN
      Finite<f64> | none8 BNaN, ±∞
      Positive<i32> | none4 B음수
      Positive<u32> | none8 B (태그)없음

      niche 값이 0 인 경우 (NonZero) 항의 비트는 그대로이므로 NonZero<T> | none 은 C ABI 를 0 이 none 인 정수로 건넙니다.

      #2.2.2. NonZero<T> - 0 금지

      trait NicheInt { .. }            // 10 개의 정수 타입이 구현

#[niche(0)]
struct NonZero<T>(T);

impl<T: NicheInt> NonZero<T> {
    fn new(value: T) -> NonZero<T> | none;
    unsafe fn new_unchecked(value: T) -> NonZero<T>;   // value == 0 이면 UB
    fn get(self) -> T;
}

      정수 타입만 받습니다. 부동소수는 NonNan / Finite 를 씁니다.

      연산결과
      NonZero<T> * NonZero<T>NonZero<T>. 곱이 wrap 되어 0 이 되면 panic
      NonZero<T> + - / NonZero<T>T
      T / NonZero<T>T. 0 으로 나누기가 없음

      TryFrom<T> 는 0 이면 ZeroError 를 던집니다. From<NonZero<T>> for T 는 lossless 입니다.

      let n: NonZero<i32> = NonZero::new(42) ?? panic("zero");
let nz: NonZero<i32> = try 7.try_into();
let v: i32 = nz.into();

      #2.2.3. NonNan<F> - NaN 금지

      trait NicheFloat { .. }          // f32, f64 가 구현

#[niche(F::NAN)]
struct NonNan<F>(F);

impl<F: NicheFloat> NonNan<F> {
    fn new(value: F) -> NonNan<F> | none;
    unsafe fn new_unchecked(value: F) -> NonNan<F>;    // NaN 이면 UB
    fn get(self) -> F;
}
      • Eq, Ord, Hash 를 구현합니다. -0.0 == 0.0 이며 해시도 같습니다.
      • + - * / 의 결과는 F 입니다 (∞ − ∞ 등이 NaN 일 수 있음).
      • TryFrom<F> 는 NaN 이면 ConversionError 를 던집니다.

      #2.2.4. Finite<F> - NaN, ±∞ 금지

      #[niche(F::NAN, F::INFINITY, F::NEG_INFINITY)]
struct Finite<F>(F);

impl<F: NicheFloat> Finite<F> {
    fn new(value: F) -> Finite<F> | none;
    unsafe fn new_unchecked(value: F) -> Finite<F>;    // NaN / ±∞ 이면 UB
    fn get(self) -> F;
}
      • Eq, Ord, Hash 를 구현합니다. -0.0 == 0.0 입니다.
      • + - * 는 Result<Finite<F>, OverflowError> 입니다 (결과가 ±∞ 이면 Err).
      • TryFrom<F> 는 NaN / ±∞ 이면 ConversionError 를 던집니다.

      #2.2.5. Positive<T> - 음수 금지

      #[niche(T::MIN..=-1)]
struct Positive<T>(T);

impl<T: NicheInt> Positive<T> {
    fn new(value: T) -> Positive<T> | none;            // 음수면 none. 0 은 포함
    unsafe fn new_unchecked(value: T) -> Positive<T>;
    fn get(self) -> T;
}

      0 이상의 값입니다. unsigned T 에는 음수가 없으므로 niche 가 없습니다.

      #2.2.6. new_unchecked

      new_unchecked 는 unsafe fn 입니다. 불변을 어기면 정의되지 않은 동작이며, T | none 이 값을 none 으로 읽을 수 있습니다.

      let n: i32 = compute();                                // 0 이 아님을 호출자가 보장
let nz: NonZero<i32> = unsafe { NonZero::new_unchecked(n) };

      #2.2.7. 검증

      • const 자리에서 NonZero::new(0) 등은 컴파일 타임에 평가되어 none 입니다. ?? panic(..) 이 붙으면 컴파일 에러입니다 (refs-lang 5.2.4).
      • 런타임에는 new (T | none) 와 try_from (throw) 으로 검증합니다.

      #2.2.8. 정의 요약

      타입bound#[niche]
      NonZero<T>NicheInt0
      Positive<T>NicheIntT::MIN..=-1
      NonNan<F>NicheFloatF::NAN
      Finite<F>NicheFloatF::NAN, F::INFINITY, F::NEG_INFINITY
