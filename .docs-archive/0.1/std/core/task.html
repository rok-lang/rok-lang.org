      rok::core::task

      rok::core::task: tasks on the work-stealing executor (stdlib 2.18, refs-lang 7.6) and block_on (2.20.6); time is task::time.

      One executor per process, started on first use: N workers on threads that live as long as the process (N = online CPUs or ROK_WORKERS), the blocking lane and the I/O driver. block_on and par::* attach the calling thread as a guest until their future and its spawn_local tasks are done. Without threads (wasm32-wasi, the browser) the guest runs everything itself, waiting in rok_io_wait.

      A worker has a local queue (spawn_local, never stolen) and a Chase-Lev deque; guests have neither and push to the shared injector. A worker takes from its local queue, its deque, the injector, then steals; the owner takes FIFO too, since LIFO lets a self-waking task (yield_now) starve the rest of its deque.

      A task's state goes IDLE -> SCHEDULED -> RUNNING -> IDLE / DONE; a wake while RUNNING marks it NOTIFIED and it is queued again after the poll.

      Idle workers sleep on a flag; a push wakes one flagged worker, which searches until it finds work, and the last searcher to find a task wakes the next (tokio's scheme). No worker spins before sleeping.

      I/O (707): a driver thread blocks in kqueue / epoll and unparks the tasks waiting on a ready fd.

      Blocking calls (706 §7.6.7): each pool thread has a runtime lane that is marked blocked for the length of a blocking call. A monitor scans the lanes every millisecond; a worker blocked across a whole scan is handed to a spare or new thread, and the blocked thread finishes its poll as an orphan guest, then waits as a spare (10 s, then exits). At most 512 extra threads. A worker with live spawn_local tasks is never handed on.

      Cancellation (2.18.4, 707 §7.7.10): Task::cancel sets a flag and wakes the task; each await checks it on entry and after each resume and leaves the body like a return, running finally / using.

      Timers: one binary heap behind a Mutex (707 §7.7.5).

      ROK_THREAD_PER_CORE=1 (706 §7.6.8) keeps every task on one worker's local queue, so nothing is stolen. ROK_DYNAMIC_WORKERS=1 (707 §7.7.8) wakes only active workers and activates one more when all are busy.

      REPL sessions are saved between cells (rok_session_hold): every executor thread is busy from rok_session_enter to rok_session_leave except while asleep, and parks at rok_session_pass (between tasks, holding no lock) while a hold is requested, so no task is mid-poll in a saved session.

      unwinding

      pub fn unwinding(ctx: Context) -> bool

      Whether a future that just returned Ready with ctx may have left because of a cancel (its value is then a placeholder): the await after a ready poll checks this, not the bare flag, so a value a hand-written future handed over (a message, a guard) is kept when the cancel lands meanwhile - the next cancellation point leaves.

      spawn

      pub fn spawn<F: Future + Send>(fut: F) -> Task<F::Output> where F::Output: Send

      Run fut as a new task on any worker, concurrently with the spawner (2.18.1). Needs a running executor (inside async fn main / block_on). The task gets its own copy of every collection fut holds, what its coroutine captured included (2.13.9): the spawner keeps the originals.

      spawn_local

      pub fn spawn_local<F: Future>(fut: F) -> Task<F::Output>

      Run fut as a new task on this worker only (it need not be Send). From a task a block_on thread happens to poll, that is one pool worker, and the task starts once that poll ends.

      select

      pub const fn select<F: Future>(futs: List<F>) -> SelectFuture<F>

      The first of futs to complete, with its index: let (i, v) = await task::select([a, b]) (refs-lang 4.12.9 names select; 2.18 gives no signature). Unlike race the futures are not spawned: they run inside the awaiting task, polled in list order (ties go to the lower index). The futures share one type: async { .. } blocks with the same output do (wrap differing outputs, async { Msg::A(await a) }). Once one completes, every other one that has started is polled once more as cancelled (its await leaves through finally / using, as for Task::cancel) and dropped. Panics on an empty list.

      spawn_blocking

      pub fn spawn_blocking<T: Send>(f: fn() -> T + Send) -> Blocking<T>

      Run f on the executor's blocking lane; the future completes with its result (tokio's spawn_blocking). For syscalls with no readiness to wait on, like regular files under kqueue / epoll. f is queued at once; a cancelled awaiter leaves it to finish in the background and its result is dropped.
