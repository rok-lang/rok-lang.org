      #Generators

      Write the Fibonacci sequence, a prime stream, a hand-made take_while adapter and a recursive tree walk as lazy iterators with yield fn.

      #Code

      // An endless Fibonacci stream.
yield fn fibonacci() -> i64 {
    let a = 0i64;
    let b = 1i64;
    loop {
        yield a;
        let next = a + b;
        a = b;
        b = next;
    }
}

// Primes by trial division against the primes found so far.
yield fn primes() -> i64 {
    let found: List<i64> = [];
    let n = 2i64;
    loop {
        let is_prime = true;
        for p in found {
            if p * p > n { break; }
            if n % p == 0 { is_prime = false; break; }
        }
        if is_prime {
            found.push(n);
            yield n;
        }
        n += 1;
    }
}

// A generic adapter: pass items through until `pred` fails.
yield fn take_while<I: Iterator>(it: I, pred: fn(I::Item) -> bool) -> I::Item {
    for x in it {
        if !pred(x) { return; }
        yield x;
    }
}

// A nested list, walked depth-first by a recursive generator.
enum Tree {
    Leaf(str),
    Branch(List<Tree>),
}

yield fn leaves(t: Tree) -> str {
    match t {
        Tree::Leaf(name) => yield name,
        Tree::Branch(kids) => for k in kids {
            for name in leaves(k) { yield name; }
        },
    }
}

let first: List<i64> = fibonacci().take(12).collect();
println(f"fib: {first:?}");

let small: List<i64> = take_while(primes(), |p| p < 50).collect();
println(f"primes < 50: {small:?}");

let even_fib_sum = take_while(fibonacci(), |x| x < 4_000_000)
    .filter(|x| x % 2 == 0)
    .sum();
println(f"sum of even fib < 4M: {even_fib_sum}");

// The 1000th prime: nothing past it is ever computed.
println(f"1000th prime: {primes().nth(999) ?? -1}");

// An inline generator block.
let squares = yield {
    for i in 1i64..=5 { yield i * i; }
};
println(f"squares: {squares.collect::<List<i64>>():?}");

let tree = Tree::Branch([
    Tree::Leaf("a"),
    Tree::Branch([Tree::Leaf("b"), Tree::Branch([Tree::Leaf("c")]), Tree::Leaf("d")]),
    Tree::Leaf("e"),
]);
let names: List<str> = leaves(tree).collect();
println(f"leaves: {names:?}");

      #Walkthrough

      • Calling a yield fn doesn't run its body right away; it returns an iterator, GenIter<T>. The -> i64 is not a return value but the type of the yielded items (4.11.3 named generator functions).
      • fibonacci() and primes() are infinite generators. Their locals (a, b, found) are preserved between yields, and the consumer pulls only as many items as it needs with take, nth and the like (4.11.9 infinite generators).
      • Generators implement Iterator, so they combine with adapters such as filter, sum and collect. A take_while, which the standard iterator lacks, is a single generic yield fn that ends iteration with return; (Collections and iterators, Generics).
      • yield { ... } is an inline generator block that builds an iterator right where an expression is expected (4.11.4).
      • leaves calls itself and re-yields the values of each subtree. Recursive generators are a common way to flatten nested structures (Sum types).

      Note

      An enum that contains itself directly, like Node(Tree, i64, Tree), has infinite size, so the compiler rejects it (a struct / enum can't contain itself by value). This example keeps the children in a List<Tree>, a reference type, to express the same structure.
